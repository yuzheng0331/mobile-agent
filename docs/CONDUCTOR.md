# 主控规程

**只给主控读。** 子智能体不需要这一份，委派时也不要给它们。

## 1. 角色

| 角色 | 干什么 | 不干什么 |
|---|---|---|
| 主控（我） | 写任务卡、判 PASS/FAIL、维护文档、跨模块一致性 | 不写实现、不读完整产出 |
| **Claude Code** | **落地**：改代码、跑测试、写回执 | 不做跨文件重构决策；不改 `docs/` |
| **Codex** | **只审**：读 diff 与目标文件，给阻断级/建议级意见 | 不写文件；不改代码；不看 `docs/` |

codex 的审查结论只作参考，不构成合入依据——合入由我按测试与断言判。

## 2. 分档

| 档 | 触发 | 交付物 |
|---|---|---|
| T1 微改 | ≤30 行、单文件、不碰不变量 | 零文档：一句话 + 目标文件 + 跑测试 |
| T2 新能力 | 单模块、新函数或新字段 | 任务卡 ≤15 行（见 `specs/CARD.md`），贴在委派里，不落文件 |
| T3 结构性 | 跨模块 / 改不变量 / 改包格式 | `specs/T-xxx.md`，≤40 行，必须含验收命令 |

拿不准就往上靠一档。做完发现是 T1，下次降。

## 3. 委派前四条自检

1. **卡片行数**：`(Get-Content specs\T-012.md).Count` ≤ 15。超了就升 T3。
2. **输入三样**：只给目标文件路径、任务卡、该模块的 `CLAUDE.md`。不给会话历史，不给 `docs/research/`、`docs/DECISIONS.md`。
3. **判断留我**：优先级、取舍、边界、做到什么程度——这些没写进卡。卡里只有“什么叫通过”。
4. **验收可执行**：每条验收是一个命令加一个机器判据。写“看起来对”的，等于没验收。

## 4. 评审（Codex）

触发：T3、改不变量、改包格式、单次 diff > 200 行。其余不审，省时间。

给它的输入只有两样：`git diff` 的文本、被改的文件路径。不给任务卡以外的动机。

它的输出固定四段，少一段就打回：

```
① 阻断级：会坏、会错、会漏（文件:行号 + 为什么）
② 建议级：可改可不改
③ 判断不了：需要人看的
④ 结论：能合 / 不能合
```

我只处理 ① 和 ③；② 记进 `STATE.md` 的待办，不打断当前单。

一次评审只审一个 diff，不并发。

## 5. 判定

只读三样：**断言输出、退出码、回执单行**。不重跑、不看代码风格、不问“为什么这么写”。

report 里出现“符合预期”“大致”“应该没问题”就是 FAIL，让它补实际数值。

## 6. 收尾

- `docs/STATE.md`：改「里程碑现状」和「下一步」两段，覆盖旧的。
- `docs/DECISIONS.md`：只追加，不改旧条目。
- 不把现状写进 `ARCHITECTURE.md`——那份只描述设计。

## 7. 越界红线

- 要动 `D:\dsh-alt\profiles\`、凭据、注册表、系统服务：先贴 diff，等一句确认。
- 要写仓库外的路径：先报绝对路径。
- 用户的句子是问句（为什么 / 能不能 / 是否）时，只回答，不动手。

## 8. 反例库（主控自己犯的）

**#1 把单次观测当机制**（2026-11-19）

- 证据：一次 `Edit` 被拒，报错写 provider 不请求审批
- 错：判定“这个通道只能只读，写文件得我来”
- 对：那是 provider 实例的默认配置，包里有开关
- 代价：分工白换一轮，用户追问才发现

**#2 没授权就改环境**（2026-11-19）

- 证据：用户问“能不能让他接受”，我直接改了 `cordis.patch.yml`
- 错：把“能不能”读成“去改”
- 对：先答三档差异，等一句确认再写
- 代价：回滚一次，信任成本比改动本身高
