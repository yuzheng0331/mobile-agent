# 任务卡模板（T2）

15 行是天花板，不是目标。典型 6–10 行。**写长了说明决策还没做完**——那是主控的活，不是子智能体的。

## 槽位与上限

| 槽 | 写什么 | 上限 |
|---|---|---|
| 目标 | 改什么、改完什么行为变了 | 2 行 |
| 接口 | 逐字签名，含默认值与返回类型 | 4 行 |
| 验收 | 命令 + 机器可判的判据 | 4 行 |
| 禁止 | 最容易越界的 3 条 | 3 行 |
| 回执 | 报告写哪、只写什么 | 2 行 |

## 模板

```
# T-012 <一句话标题>
目标：<改什么；改完什么行为变了>
接口：<签名逐字，含默认值>
验收：<命令>；<判据>
禁止：<不许碰的文件/依赖/行为>
回执：reports/T-012.md，只写断言输出与退出码
```

## 实例（6 行）

```
# T-012 Cadence sigma
目标：wait 的间隔从指数换成对数正态，sigma 可配
接口：Cadence.next(meanMs: Long, sigma: Double = 0.9): Long
验收：./gradlew :core:test --tests '*Cadence*'；p50/p90 比值落在 0.35–0.65 / 1.6–2.6
禁止：不改 Pack.kt；不加依赖；不动 Runner 其它分支
回执：reports/T-012.md，只写断言输出与退出码
```

## 自检与升级

```powershell
(Get-Content specs\T-012.md).Count      # 必须 ≤ 15
```

- 超过 15 行，或「禁止」超过 3 条 → 判定为 T3，改走完整 spec。
- 槽位空着（尤其「验收」）→ 不许委派，先补判据。
